# CipherRoll — Cursor build prompts, native Swift (run one phase at a time)

Setup once: put the package in the repo as `docs/` (Common/Docs + `00_Native_iOS_Stack.md`) and `design/` (Common/Screens, Common/Icon). Copy `cipherroll_ios.mdc` to `.cursor/rules/`. Paste the prompts in order. Review each phase before the next.

## Phase 0 — Project setup
> Read `.cursor/rules/cipherroll_ios.mdc`, `docs/00_Native_iOS_Stack.md`, `docs/13`, `docs/11`. Create the Xcode project "CipherRoll" (SwiftUI, iOS 16+, universal: iPhone, iPad and iPhone Duo; read docs/11 section 10 first) with the folder layout from the rules. Bundle Manrope fonts and register them in Info.plist. Build a `DesignSystem` with colour, type and spacing tokens from doc 11 section 3, light and dark, and a theme preview screen. Add the Phosphor Swift package and an `Analytics` protocol with a no-op implementation. Add the Icon B asset catalog from `design/03_Icon`. Build and stop with a list of what you made.

## Phase 0A — Security design first (documents only, NO code)
> Do not write any vault code yet. Read `docs/11` section 1, 1A and 1B. Produce these documents in `docs/security/`: (1) threat model, (2) encryption architecture and key tree (item key, vault key, key from lock secret, recovery key), (3) key management: Keychain class `WhenPasscodeSetThisDeviceOnly`, PIN change, rotation, (4) Secure Enclave feasibility: it does not do AES-GCM and does not stop offline PIN guessing by itself, so show a device-bound unwrap design with rate limiting and say what recovery is lost, (5) recovery design: key covers real vaults only, never the decoy, must not reveal the decoy; decoy has own PIN and keys, no recovery, (6) Swift module structure, (7) implementation phases, (8) test plan covering: passcode removed, iPhone replaced, recovery key lost, app deleted and reinstalled, restore from backup, wrong-PIN counter after kill and reboot, temp video file cleanup after kill/crash/interrupted playback, decoy vs real analytics payload. Rules: minimum 6-digit PIN (no 4-digit), optional 8+ or alphanumeric; V1 local-only and excluded from backup; protected temp video files allowed only as a documented trade-off; never claim forensic erasure. Do not mark any security requirement complete without reproducible test evidence. Stop and give Praba a short summary plus open questions (include: encrypted export and restore for V1). Do not start Phase 1 until the documents are signed off.

## Phase 1 — Security core (gate items 1 to 7)
> Build the vault storage layer only, no UI. Follow the Security section of the rules: CryptoKit AES.GCM per item, key wrapping, Keychain, PBKDF2 (or Argon2id) key derivation, complete file protection, excluded from backup, no readable temp files, memory wiping of keys. Add: create vault, add item, read item to memory, delete item, change lock secret, recovery key (generate, test, unlock with it), wrong-attempt counter with growing delay that survives app restart. Write XCTests, including one proving raw files on disk are not readable as the original. Stop with a short report for Praba: the security gate table (items 1 to 7) with the test names and results as proof. Use a 6-digit minimum PIN, protected temp files for video only, recovery key for real vaults only, decoy with its own PIN and keys and no recovery. Mark nothing complete without a passing test.

## Phase 8 — iPad and iPhone Duo pass
> Read `docs/11` section 10 and `design/screens/10_iPad_and_Duo` and `design/screens/11_iPhone_Duo`. Make every feature work on iPad and iPhone Duo using adaptive layouts: sidebar split view in regular width, centered sheets for import, export, restore and paywall, adaptive photo grid, viewer with details panel, all orientations, Split View and Stage Manager. No device-model checks, no `UIScreen.main`. Replace hardcoded "Face ID" text with `LAContext.biometryType`. Test on iPhone SE, iPhone Pro Max, iPad mini, iPad Pro 13, narrow and half Split View, and the iPhone Duo simulator (closed, open, half-folded). Build with Xcode 27.1 and the iOS 27.1 SDK or later (Flutter: the matching Xcode). On the Duo outer display use the standard vertical bar (tabs need a title and an icon), handle asymmetric safe areas, keep state through fold and unfold, and show Touch ID where Face ID is not available. Stop with screenshots of each.
